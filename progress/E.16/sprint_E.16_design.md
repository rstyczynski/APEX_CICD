# E.16 design

Status: Accepted (YOLO self-approval).

Use a dedicated sanitized GitHub repository, pinned E.15 Oracle image and pinned SQLcl 25.4.1.022.0618 with Java 21. Native project metadata must be generated by that release; older application metadata is unchanged. Prepare one table release then an additive column upgrade, retain a seeded row, and repeat the exact qualified upgrade archive. Keep source commits, native stage/verify/release/package logs, archive digests and target observations. Deployment must compare trusted evidence with selected source, metadata version/build and archive bytes before invoking native PROJECT deploy. Receipt changes and corrupt bytes must reject without target mutation.

### Testing Strategy

Test and Regression are smoke, unit, integration, full scope. New smoke checks syntax and layout. Unit checks provenance refusal paths with no Oracle claims. Integration executes real native lifecycle on hosted Oracle. Full regression uses unfiltered tests/run.sh for all three levels. Timestamp logs and retained workflow artifacts provide evidence, never replace live demo.

## Test Specification

SM-16 checks Python compilation and workflow shape. UT-16 rejects changed archive, changed source and incompatible tool. IT-16 performs native initial deployment, seeded-data upgrade, exact repeat and negative preflight cases on the E.15 hosted execution boundary. Any failed native operation remains a failure even if process exit is zero. No simulation substitutes for IT-16.

## Authorized Actions refactor

The Product Owner's correction replaces the Python lifecycle controller with named GitHub Actions steps. [The correction design/checklist](sprint_E.16_actions_refactor.md) owns the updated implementation boundaries and revalidation; the standing native-technology rule applies. The bounded native fixture and R1–R6 acceptance remain unchanged. Design self-reviewed under the existing YOLO delegation: Actions sequences, SQLcl PROJECT performs lifecycle operations, Git records history, and Python performs only small checks. The earlier controller design is retained as history, not the current architecture.
