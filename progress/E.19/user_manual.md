# E.19 operating reference

Use the [complete walkthrough](sprint_E.19_increment_demo.md) as the entry point. It discloses the platform/native automation and complete SQL sources before invocation, gives portable commands, maps slides and distinguishes fresh dispatch from retained run inspection. The [catalogue](../../sprint-work/E.19/CATALOGUE.md) owns guard inputs/outputs/refusals. The [inventory](sprint_E.19_inventory.md) explains historical and application-test scope.

Supported tasks are validating SQLcl identity/native metadata, detecting native output errors, binding exact archive/source/tool evidence, validating candidate identity and binding trusted Review to candidate bytes. Normal workflow success dependencies must guard target writes. A required file must exist as a regular nonsymlink input; workflow producers supply its authority and freshness. validated=true is emitted only after success. Shared code and action subdirectories must be checked out together. Pin consumed action source to a reviewed immutable commit.

The five guards use GitHub's Node24 action runtime and no npm dependencies or Python. Native qualification additionally needs hosted Docker/JDK/SQLcl/APEX/ORDS setup, declared visibly in native.yml. The separate Oracle application regression still uses pinned Python oracledb; the benchmark deliberately retains Python comparison. Neither is included in the Python-free guard-runtime claim.

On failure inspect the named action, actual tool log, current native metadata, independently expected commit and receipt hash. Correct the producer or supported inputs and rerun. Do not bypass guards with continue-on-error, supply untrusted expectations or edit project metadata to silence compatibility checks. Fresh hosted native jobs clean generated private inputs/profiles and owned containers even on failure. Preserve exact retained artifacts and logs when diagnosing a mismatch. No local scratch credential deletion is part of this procedure.

No OCI interaction is delivered. Future selected OCI calls must use Oracle's official JavaScript/TypeScript SDK. Real hosted observations qualify this bounded Elaboration validation; production rollout and Lifecycle Architecture remain separate decisions. The [comparison](comparison_report.md) gives measured limits, and the [handover](sprint_E.19_handover.md) owns final lifecycle evidence.
