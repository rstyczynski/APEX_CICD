# I.1 — Inspecting the Inception baseline

## Supported task and prerequisites

This increment supports inspection of the accepted analysis, not operation of an APEX delivery pipeline. Use this checkout and a Markdown reader; a presentation viewer is needed only for the deck. Oracle, Podman and credentials are unnecessary for the artifact review.

Follow the nine stages of the [presentation walkthrough](sprint_I.1_increment_demo.md) in order. It supplies the actual document links, expected observations, slide references and requirement/PBI associations. Start with the scope, inspect the six final review decisions, follow Foundation-first assembly and the developer cycle, then inspect the future success/failure evidence and Elaboration checkpoint. The [handover](sprint_I.1_handover.md) records the acceptance boundary and remaining decision.

## Limits and recovery

The SRS defines expected behavior; the architecture recommends candidate mechanisms. No reservation controller, greeting application, qualified artifact, maintained runtime state or automated repair is delivered in I.1. Do not run the future commands in the test profile as if they already existed. The infrastructure runbook has its own operating prerequisites and retained-data rules; it is not executed during this artifact review.

If a document link fails, retain the checkout, report the broken link and correct the document before accepting handover. If the viewer cannot display the artifacts, record that limitation and complete the review when display is available. Deck rendering is evidence of presentation preparation, not evidence that the Product Owner saw a live demonstration.

Supporting lifecycle scripts remain untracked at this checkpoint. E.1 must review and adopt their sources before claiming reconstruction from Git. Retained runtime files, credentials and unrelated resources must remain untouched.
