# E.12 design

Status: Accepted (YOLO self-approval)

## Scope and decisions

[Setup](sprint_E.12_setup.md) defines the actors and contract. Use an isolated E12_APP schema and unchanged stored Hello/World consumers with legacy positional calls and direct table access. Add nullable language storage and a separate optional-language entry point, retaining the active legacy specification/body untouched. A transactional change journal captures inserts, updates and tombstones. Catch-up reconciles from current source under a short shared source lock at the explicitly selected boundary, rather than assuming sequence order equals commit order. No production rollout or E.13 dual-write bridge is claimed. These mechanisms and a finite workload are implementation choices, not new acceptance requirements.

### Testing Strategy

Test and regression: smoke, unit, integration, full suite. Smoke checks source parsability. Unit checks reconciliation expectations with insert/update/delete and stale snapshots. Integration uses real separate Oracle sessions, both unchanged consumers and direct legacy DML, interrupted backfill and restart. Historical suites retain their actual infrastructure prerequisites. No mock can establish availability or migration correctness.

## Test Specification

SM-1: compile Python experiment without executing SQL. UT-1: compare complete keyed representations; reject missing, duplicate and stale values. IT-1: run both legacy consumers during additive schema changes and interrupted migration; verify journal attribution, identifiers, no lost/duplicated changes, preserved baseline history/configuration, and optional language behavior. Real workload errors fail the experiment. A finite successful sample establishes availability for that sample, not a universal zero-downtime bound.

## Requirement and verification ownership

The maintained [requirement-to-evidence checklist](sprint_E.12_remaining_work.md) maps BACKLOG PBI-048/PBI-081, PLAN's six selected gates, patch P8/P9 and canonical closure to their current evidence. This design defines the test specification; it does not override acceptance or claim a gate passed before its recorded exit. No acceptance item is waived by YOLO thresholds.

## Bounded availability profile

The [original combined scope](../E.5/sprint_E.5_proposedchanges.md#required-design-decisions-before-implementation) and [test profile](../../docs/test-profile.md#status-and-purpose) require explicit measurable limits. The existing driver enforces a 180-second subprocess deadline on every SQL operation, including each complete 120-call consumer stream and catch-up session. This is the maximum permitted client-observed operation/lock wait budget for this laboratory experiment; exceeding it fails the run and requires diagnosis, not an availability pass. There is no allowed failed supported-consumer call. It is an implementation budget, not a production service-level objective, and no independent server-side lock timeout or universal lock-duration bound is claimed.

The 0.1-second pauses intentionally separate committed consumer calls. Server completion timestamps provide an observed upper bound on the intervening call's work, including that pause and client parsing, rather than a pure database latency measurement. tests/availability-observations.json records the actual 120-call sequences, completion gaps and spans. Together with traffic before/during/after expansion and recovery, these measurements make the finite availability claim assessable without pretending that an unmeasured production latency target passed.

## Prepared-host credential accommodation and native profiles

AGENTS.md permits only read-only use of the retained E.1/E.2 record for the approved prepared-host lookups; it does not authorize treating scratch saved connections or root credentials as current authority. The default author SQL path therefore reads the existing author-schema password from that record, connects directly in memory, and uses a temporary native SQLcl home that is removed after the call. It does not read retired credentials.env, save a connection or copy/move/rewrite the retained record. Administrative/provisioning calls require explicit private inputs outside checkout, and explicit native profile paths inside checkout are rejected. Default native profile selection uses the user's normal home rather than checkout scratch; integration supplies its own temporary profile explicitly.

The private-boundary unit case adds checks for this approved default author path, its temporary-home cleanup, rejection of a checkout profile and refusal of default administrative/provisioning inputs. These complement real author composition/history tests executed with the new default path. This is a configuration-policy correction found during final audit, not a claim that the temporary accommodation now meets production NFR-4 or that its retained record may be discarded.

## Runner input ownership repair

The real isolated two-case reproduction in tests/runner-stdin-defect.log showed that a child draining stdin consumes the runner manifest and silently omits the next case. YOLO-approved UT-REG-2 extends the existing actual-runner test with an input-draining child followed by a required second case. Each noninteractive test subprocess receives /dev/null as its inherited stdin; tests needing input already supply explicit subprocess input. This is a selection repair needed for PLAN full regression, not a new product acceptance requirement. The final full run must execute all 21 integration entries from a frozen source snapshot and retain before/after source hashes.
