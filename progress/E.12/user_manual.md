# E.12 operator reference

The [complete walkthrough](sprint_E.12_increment_demo.md) explains the exact SQL before its invocation and maps the [deck](sprint_E.12_increment_demo.pptx). Use it in execution order. [Design](sprint_E.12_design.md) owns experimental choices; [tests](sprint_E.12_tests.md) owns verified outcomes. Prerequisites are the prepared Oracle Podman service, Python 3, Git and code on PATH. No new host reproduction is implied.

Supported tasks are compatible schema expansion, unchanged PL/SQL consumer traffic, optional-language evaluation, interrupted backfill and locked-boundary catch-up. Each run retains an isolated schema named in experiment.json. The expected interrupted transaction is recovered in place by rollback and catch-up within that same run. After an unexpected infrastructure failure, inspect its retained SQL/logs and start a fresh isolated run. Do not drop a schema solely because its name begins with E12. Fixture cleanup needs the ownership marker and confirmation that no client uses it. This iteration does not change retained application schemas, retained credentials or SQLcl PROJECT metadata. A finite traffic sample cannot prove universal availability or a production latency target.

## Full historical regression environment

The full integration command also selects older E.1 delivery cases. Those now run in the dedicated FREEPDB1 in the separate labelled e12-regression-db container, rather than treating retained native UAT as the old custom-controller baseline. The integration runner prepares the separate database when absent, verifies and installs cached APEX 24.2, requires the E12 ownership marker before reusing it, and prepares separate logical E.1 workspaces. It creates a temporary ORDS instance on a loopback port and native SQLcl profiles in an OS-private temporary directory. It removes the instance, private configuration volume and temporary files on exit. Existing images, SQLcl/JDK and APEX installation files are read-only tool caches. This is a prepared-host regression facility, not a production or new-host deployment recipe.

The regression fixture's runtime service is 127.0.0.1:1551/FREEPDB1. Evidence records that binding separately from the archived logical configuration hash. The selected historical native controllers require SQLcl 25.3.0.274.1210 and verify Database 23.26.3.0.0/APEX 24.2.0. No SQLcl PROJECT export, stage, release or deploy is performed by this fixture. The maintained root test profile owns test selection; the sprint test record owns current results. A new hosted PR or remote publication is not created by local regression.

Before running full regression, the wrapper explains and performs these operations through [legacy_regression.py](../../tests/legacy_regression.py) and [legacy_release.py](../../tests/legacy_release.py): native schema/workspace creation, archive validation, fresh reconstruction, same-byte initial/patch qualification and promotion, deliberate preflight faults and authenticated HTTP submissions. Fixture data is explicitly created after installation and is excluded from release archives. The old retained UAT is never reset by these isolated cases. Historical test-output files written by other suites must be preserved under E.12 and their tracked historical paths restored before a completion commit.

The database preparer is [legacy_database.py](../../tests/legacy_database.py). It records and verifies ownership before reuse; the suite serializes access to this one regression fixture. The prepared-host author fallback reads only the explicitly retained e1-secrets.json accommodation, opens an in-memory direct connection and removes its temporary SQLcl home after use. Administrative/provisioning calls require explicit private state outside the checkout. This does not end the temporary accommodation or establish production NFR-4 compliance.
