# E.16 native provenance experiment

This disposable hosted experiment uses the E.15 pinned Oracle image and a checksum-pinned SQLcl 25.4.1.022.0618 download. It prepares native PROJECT releases, installs, upgrades and repeats into an isolated target. The APEX_CICD progress repository owns acceptance and lifecycle records under progress/E.16; repository existence or a dispatched run is not completion evidence.

The workflow initializes two disposable schemas. Named GitHub Actions steps record tool identity, initialize native metadata, export and stage source, verify changes, prepare releases and package native archives. SQLcl PROJECT implements these native operations. sql.sh performs a version probe and one SQL payload invocation per call; small Python checks validate measured tool/output and provenance. Before deployment, provenance.py compares source, build and archive digest. Oracle assertions check the seeded row after upgrade/repeat. Negative preflight checks do not call deployment. Workflow artifacts retain logs, receipts, archives and a Git bundle. Runner disposal removes the Oracle service and job-private material. No retained laboratory credential is used.

Run with `gh workflow run native.yml --repo rstyczynski/APEX_CICD_E.16` and inspect the actual terminal result. This is a bounded Elaboration experiment, not production multi-user authority or full APEX qualification.

The [accepted correction and evidence](https://github.com/rstyczynski/APEX_CICD/blob/main/progress/E.16/sprint_E.16_actions_refactor.md) live in the progress repository. Its [standing project rule](https://github.com/rstyczynski/APEX_CICD/blob/main/AGENTS.md#use-core-technologies-for-their-native-responsibilities) applies here: Actions sequences, SQLcl PROJECT releases/deploys, Git records history and helpers only support those native responsibilities. Stop and report an evidenced core-technology mismatch to the Product Owner before any replacement.

build_deck.mjs is authoring source for the progress repository's handover artifact, using the supplied Artifact Tool runtime and PRESENTATION_UTILS helper. It is not executed by the native delivery workflow and is not a standalone presentation service or release dependency.
